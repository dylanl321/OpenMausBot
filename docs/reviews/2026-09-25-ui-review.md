# UI review: shared tasks / connectors / Work

Date: 2026-09-25
Branch reviewed: `codex/bedrock-provider` @ `88bfd97b` (P0–P6 through PR #26)
This PR: small, safe UX fixes only. Larger redesigns stay proposals.

Dylan’s sketches and the flexible-team-work plan were inputs. The existing
layout is not treated as sacred. Preference: fewer polished surfaces over more
rough ones; kind-driven chips over provider-named chrome; honest controls that
match what the session can actually call.

No live tokens. Write locks stay off. No new connectors.

---

## What’s clean and should stay

- **Kind-driven task chrome.** `KindIcon`, `LinkChip`, `LinkCard`, `EventRow`,
  and board cards switch on `LinkKind`, not Jira/GitLab/Plane. Tests already
  forbid those names in the task panel (`src/components/work/TaskView.test.ts`,
  `LinkChip.test.ts`).
- **`ProviderMark` as a footnote.** Manifest icon or initial only
  (`src/components/work/ProviderMark.tsx`). That is the right amount of vendor
  identity.
- **Task view live path.** `TaskView` loads events once, then merges
  `subscribeWorkLive` frames. No interval. Keep this; do not reintroduce a
  per-task poll.
- **Work/goal 30s fallback.** P5 already replaced the 5s poll with SSE plus
  `WORK_FALLBACK_POLL_MS = 30_000` (`src/lib/serial-refresh.ts`). Keep the
  fallback. This PR only skips ticks on a hidden tab.
- **Manifest connection form.** `ConnectionFields` is a small
  `string | number | boolean | enum` renderer, not JSON Schema. Enough for
  current connectors. Do not grow a schema engine for four field types.
- **Goal capability gating.** `OngoingGoalPanel` already hides Start / Resume
  when the session cannot call those routes (P1 honest UX).
- **Setup Guide posture.** Server `/api/setup-wizard/*` is admin-only. UI
  entry is `ownerOrAdmin`. Copy is draft-first
  (`src/components/SetupWizardDialog.tsx:197`). Footer states Ask-mode,
  no apps/MCP/computer, no rooms/routines/skills/credentials
  (`SetupWizardDialog.tsx:358`). Community templates seed names and
  prompts only (`SetupWizardDialog.tsx:228`).
- **No write-lock Settings surface.** `features.teamMissionWrites` is
  config-file only (`docs/connectors.md`). Work, Connections, Watches, and
  Setup Guide do not expose a toggle. Keep it that way.
- **Approve once, never Always allow.** Work cards keep one-shot approve/deny
  (`src/components/WorkPage.tsx:95–101`, locked by `WorkPage.test.ts`).
- **Watches list live updates.** After hydration, watch rows patch over SSE.
  Do not add a watches poll.

## Friction / complexity / burden

Findings below cite the tree **after** this PR’s small fixes. Items marked
*fixed here* are already landed in this branch.

### Work overview is still the rough surface

- **Raw JSON as the primary decision body.** `WorkCard` dumps
  `fullRequest` or `JSON.stringify(proposal)` into a `<pre>`
  (`src/components/WorkPage.tsx:45–49, 77–79`). Skill preview sits under a
  wall of parameters. This is the heaviest control in the new Work UX.
- **Three answer UIs.** Overview inline answer (`WorkPage.tsx:173–177`),
  `WorkCard` questions / options (`WorkPage.tsx:82–108`), and room
  `TaskAnswer`. Same job, three layouts.
- **Comma-separated multi-select.** `WorkPage.tsx:88` — “Enter choices
  separated by commas” on a datalist. Fine for a fixture; cold for a
  decision-maker.
- **Hardcoded English.** Queues, filters, “Renew limits”, and gate lines
  bypass `en.json`. Room task UI is localized; overview is not.
- **Source rows plus goal rows.** A mission can emit a goal card and one
  `source:` row per inventory target (`server/routes/work-overview.ts`). The
  inbox can look like a duplicate backlog. *Fixed here:* chips are now
  `Task · Needs input` / `Goal · Paused` / `Source · {label}` instead of
  `task · needs-input` (`WorkPage.tsx:29–32`). Gate lines no longer prefix
  `budget:` / `security:` (`WorkPage.tsx:34–36, 167–169`). Scan copy is
  `Scan: complete · 4 items`, not “Inventory: … recorded item(s)”.

### Room task panel is coherent but dense

- **One panel, five sections plus an aside.** Activity filters (eight
  pills), outputs-by-kind, criteria, specialist `<details>`, evidence
  `<details>`, linked column (`TaskView.tsx:114–184`). Board users never see
  this: `GroupView` defaults to Board when work exists
  (`src/components/GroupView.tsx:920–924`) and only mounts `TaskView` on Chat.
- **Stop/Reopen stay long on purpose.** `work.stop` / `work.reopen` remain
  “Stop shared task” / “Reopen shared task” so they do not collide with
  composer Stop (`scripts/testing/shared-work-ui.e2e.test.ts` clicks those
  names). Shortening needs a unique `aria-label`, not a shorter visible
  string alone.
- **Connector actor is a connection id.** `EventRow` prints
  `actor.connectionId` (`src/components/work/EventRow.tsx:30–35`). Manifests
  are in props; connection labels are not.
- **Dead i18n.** `work.brief` and `work.workerThreads` are unused.
  `goal.panel.criteria` / `scope` / `scopeHint` / budget keys are unused and
  tests assert they stay hidden (`OngoingGoalPanel.test.ts`).
  `goal.panel.scopeHint` still says `jira:connection:PROJECT-`.
- *Fixed here:* shorter specialist / Now / link-help copy; tool-call toggle
  only when the filter is All; event fetch failures surface instead of
  `.catch(() => {})`; LinkChip shows revision/branch/key/sha only.

### Goals: three doors, one panel

- **`/goal` channel chip, `/pursue` slash, and Pursue chip** all sit on the
  composer (`src/components/Composer.tsx:533–537, 928–963`). `/goal` is a
  room channel mode. `/pursue` opens `OngoingGoalPanel`. Same Target icon,
  different products.
- **Panel is a strip, not a hub.** Latest five goals, raw action counts,
  no jump to Work (`OngoingGoalPanel.tsx:108–128`). *Fixed here:* human
  status labels and “Showing the latest 5.”
- **`GoalRunCard` is display-only.** No pause / open / follow
  (`src/components/GoalRunCard.tsx`).

### Connections

- **Settings mixes two products.** Task connections (manifest form) sit
  above Anthropic / OpenAI-compat / xAI / Mistral / Composio / VPS
  (`src/components/SettingsModal.tsx:762–793`). Same word, different job.
- **List/mutate API is admin; the panel was a 403 trap for clients.**
  *Fixed here:* `useOwnerOrAdmin` hides Add / Test / Enable / Delete and
  skips the list fetch for non-admins
  (`src/components/connections/TaskConnectionsPanel.tsx`).
- **Empty team checkboxes = all teams** is explained
  (`ConnectionEditor.tsx` teamsHelp) but easy to miss. Keep the copy; do
  not invent a third “everyone” checkbox.
- **Enabled badge named the vendor.** *Fixed here:* Enabled / Disabled;
  `ProviderMark` already identifies the connector.
- **Subtitle named Jira, GitLab, Plane.** *Fixed here:* kind-driven lede
  and empty-watch copy.

### Watches / Automations

- **Editor is one long modal:** source tiles, scope fields, event chips,
  five action types, interval, backfill, dry-run, then Advanced
  (filters, limits, batch, webhook field map). Correct power-user form;
  cold as a first watch.
- **GET is client; POST/PATCH/DELETE are admin.** *Fixed here:* New /
  pause / delete / row-edit hide for non-admins; Automations → New →
  Watch disables with “needs admin”.
- **First-item defaults.** Webhook no longer selects `webhooks[0]`
  (*fixed here*). Notify still defaults `bots[0]`; run-routine still
  defaults `routines[0]` (`WatchEditor.tsx` action buttons).
- **Complex filters are a dead-end** (`WatchFilterBuilder.tsx` read-only
  + reset). Honest, but the reset is the only way out.
- **Automations chrome is hardcoded English** (“Automations”, “Schedule”,
  “New”) in `RoutineCalendarPage.tsx:1814–1841`.

### Setup Guide

- Admin-only and drafts-only. **Do not add write-lock, credential, or
  connector grants.**
- **“Chief of Staff grant”** (`SetupWizardDialog.tsx:325`) is
  coordination, not `writes.allow`. The word “grant” is easy to misread
  next to write locks.
- **“Admins only”** in the review step is *visibility of new bots on the
  admin web*, not who may run the guide (`SetupWizardDialog.tsx:336–341`).
- Unlocalized English throughout the dialog.
- *Fixed here:* a 403 / missing admin scope reads as “Setup Guide needs a
  workspace admin.”

### Polling

| Surface | Transport | Note |
|---|---|---|
| TaskView | SSE `work.event` | Keep |
| Watches list | SSE `watch` after fetch | Keep |
| Work overview / goals | SSE + 30s fallback | Keep; skip hidden-tab ticks (*fixed here*) |
| TopicBoard | HTTP on saved query change | No live columns |
| ConnectorCard OAuth | 4s poll, 75 tries | Unrelated leftover; do not copy |

Do not lower the 30s fallback. Do not add a Settings poll for connections.

## Proposals

### P0 — do these next if anything else ships

1. **Replace WorkCard `<pre>` JSON with a structured summary.** Title,
   tool/skill name, one-line why, then `<details>` for raw parameters.
   Keep Approve once / Deny. This is the largest remaining burden on the
   overview. Do not add Always allow.
2. **One pending-action renderer** shared by Work overview, `WorkCard`,
   and `TaskAnswer`. Same answer box, same question list, same approve
   pair. Delete the comma-separated multi-select or replace it with
   option chips.
3. **Keep Connections mutate and Watch create admin-only in the UI.**
   Already done in this PR. Do not regress by showing Add to clients.

### P1 — simplify without a rewrite

4. **Unify goal language.** Pick one door: Pursue opens the panel;
   `/goal` stays a room channel *or* is renamed so it does not look like
   the same product. Put a “See all on Work” link on the panel when more
   than five goals exist.
5. **TaskView progressive disclosure.** Default: Now + criteria +
   activity. Collapse outputs, linked, evidence, specialists unless
   non-empty and relevant. Or three tabs: Now / Activity / Links.
   Do not add a sixth section.
6. **Watch editor as four steps:** source → match (events + optional
   filter) → action → test & save. Keep Advanced collapsed. Require an
   explicit bot / routine the same way this PR requires an explicit
   webhook.
7. **Split Settings “Connections”.** Task trackers as their own card
   (done) is not enough; the page title still means API keys. Rename the
   keys card or move trackers under a “Trackers” section.
8. **Board and Chat.** Defaulting to Board hides the only rich task
   panel. Either split the pane or remember last pane per room. Do not
   mount a second full `TaskView` on the board.
9. **EventRow connection labels.** Pass connection listings (or a
   `connectionId → label` map) so actors read “Acme tracker”, not
   `gitlab-main`.
10. **Delete or never resurrect dead goal fields.** `goal.panel.criteria`,
    `scope`, `scopeHint` (`jira:connection:…`), budget inputs. The create
    form should stay one textarea.

### P2 — later, only if the surfaces stay

11. **Localize WorkPage and Setup Guide** once copy settles. Do not
    localize first and redesign second.
12. **Shared `ManifestFieldForm`** for connections + watch scopes (drop
    the duplicate renderer). Still not JSON Schema.
13. **TopicBoard live columns** via `subscribeWorkLive`. Optional; the
    board is a query snapshot today.
14. **`GoalRunCard` actions** (open panel / open Work row). Only after
    goal language is unified.
15. **Short Stop / Reopen** with a unique aria-label, then update
    `shared-work-ui.e2e.test.ts`. Do not shorten the accessible name
    to “Stop”.

## Do not do

- **Do not add a Settings toggle for write locks.** Config-file only,
  default off, same posture as `sharedComputers`
  (`docs/connectors.md`, plan §12.3). If an admin panel is ever required,
  it must be explicit, default off, and never offered by Setup Guide.
- **Do not let Setup Guide grant write locks, connectors, credentials,
  apps, MCP, computer, rooms, routines, or skills.** Drafts create bots
  in Ask. `appHints` stay informational.
- **Do not enable `features.teamMissionWrites`, connection
  `writes.enabled`, or `writes.allow` in repo config, CI, or a UI.**
- **Do not add Always allow / blanket grants** on Work cards.
- **Do not add new connectors** in a UI cleanup.
- **Do not put provider names back on kind chips.** Manifest names belong
  on `ProviderMark` and connection labels only.
- **Do not resurrect the old goal create fields** (criteria, identity
  prefix, budget inputs).
- **Do not poll Work or goals faster than 30s.** SSE already refreshes
  on frames.
- **Do not verify against live tokens or the user’s running app.**
  Isolated fixtures only.
- **Do not add a sample-data generator.**
